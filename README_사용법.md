# 정년연장·계속고용 DSS — 설치·실행 가이드

## 0. 준비물
Python 3.10 이상. 설치 여부 확인: 터미널(윈도우는 PowerShell)에서 `python --version`

## 1. 폴더 만들기
아무 곳에나 폴더 하나를 만든다. 예: `C:\Users\내이름\retirement_dss`
내가 준 파일 **전부**를 이 폴더 하나에 넣는다. 하위 폴더는 딱 하나, `.streamlit`만 만들고 그 안에 config.toml을 넣는다. 나머지는 전부 최상위에.

필수 파일 체크리스트 (하나라도 빠지면 실행 안 됨):
```
engine_retirement_v2.py      ← 시뮬레이션 엔진
dss_layer.py                 ← 시나리오·파레토·민감도
validation_v2.py             ← 검증 8종(자동 계산 5 + 근거 문서화 2 + 가정 검정 1)
llm_report.py                ← AI 해석 층
report_generator.py          ← PDF 생성기
run_pipeline.py              ← 전체 실행 스크립트
app.py                       ← 웹앱 (STRATA)
.streamlit/config.toml       ← 테마 설정 (★반드시 .streamlit 하위폴더에)
params_v2.json               ← 실측 파라미터 (필수 데이터)
big_firm_sample_2023.csv     ← KLIPS 대기업 실표본 (필수 데이터)
did_results.json             ← DiD 결과
refit_coefficients.json      ← 재적합 계수
event_study.csv              ← 이벤트 스터디
```

## 2. 라이브러리 설치 (최초 1회)
터미널에서 방금 만든 폴더로 이동한 뒤:
```
cd C:\Users\내이름\retirement_dss
pip install numpy pandas streamlit plotly matplotlib reportlab statsmodels
```
AI 해석 리포트를 실시간 생성하려면(선택, 없어도 오프라인 렌더러로 동작):
```
pip install anthropic
```
그리고 터미널에서 `ANTHROPIC_API_KEY` 환경변수를 설정한다(윈도우 PowerShell:
`$env:ANTHROPIC_API_KEY="본인 키"`). 키가 없으면 앱은 자동으로 결정론적 오프라인
템플릿으로 대체하며, 화면에 "오프라인 렌더러" 배지로 표시된다 — 앱이 죽지 않는다.

## 3. 실행 방법 3가지

**웹앱 (주력)**
```
streamlit run app.py
```
브라우저가 자동으로 열린다 (안 열리면 http://localhost:8501 접속).
사이드바가 아니라 화면 상단 가로 입력폼에 자사 프로파일을 입력 → "시나리오 분석" 클릭.
결과가 나오면 탭 4개(시나리오 비교/연도별 추이/트레이드오프 지도/민감도 분석)와
"해석 리포트 생성" 버튼이 함께 뜬다. 민감도 분석 탭은 버튼을 눌러야 계산되며(약 1분),
5×5 격자에서 재고용 수락률·임금률이 어느 지점에서 후보군 판정을 뒤집는지 히트맵으로 보여준다.

입력폼의 아래 두 칸이 결과를 가장 크게 바꾼다:

- **정년연장 부담을 흡수하는 방식** — 정원 유지 / 인건비 총액 유지 / 채용 규모 고정.
  회사가 먼저 정해야 하는 전제이며, 무엇을 고르느냐에 따라 권장 후보군이 실제로 달라진다.
- **50세 이후 임금 궤적** — 현행 관측(횡단면 곡선) / 50세 이후 동결 / 호봉제 유지.
  기본값은 현재 관측되는 연령-임금 곡선이지만, 그 곡선엔 임금피크·재고용 전환이 이미
  섞여 있어 호봉제가 정년까지 작동하는 회사에는 맞지 않는다. 호봉제로 바꾸면 정년연장의
  인건비 부담이 약 2.5배로 커진다(급진연장 기준 +0.72% → +1.83%). 단, 파레토 후보군
  구성은 세 레짐 모두 동일했다 — 결론은 견고하고 비용 규모는 그렇지 않다.

**PDF 리포트 일괄 생성**
```
python run_pipeline.py
```
약 2~3분 뒤 같은 폴더에 `executive_report.pdf` 생성.

**검증 스위트**
```
python validation_v2.py
```
8종 검증 결과가 JSON 한 줄씩 출력되고, 마지막 줄에 요약이 나온다. `method` 필드가
그 검사의 성격을 말해 주며, 세 종류를 뭉뚱그리면 안 된다:

- **computed (5종: V1·V2·V3·V5·V7)** — 지금 이 데이터로 실제 재계산해 통과/실패를 판정.
- **documented (2종: V4 외부벤치마크·V6 정년퇴직 나이식별)** — 원본 KLIPS 직업력 원자료를
  1회 분석한 결과를 인용. 이 배포본에 원자료가 없어 이 코드로는 재현 불가.
- **diagnostic (1종: V8 사전추세)** — 통과/실패가 아니라 **가정을 진단**한다. `passed`는
  구조적으로 항상 True이므로 통과 집계에 넣지 않는다(넣으면 통과 수가 부풀려진다).
  실제 판단은 `parallel_trends_ok` 필드로 한다.

그래서 "8종 전부 통과"가 아니라 **"5종 자동 계산 통과 + 2종 근거 문서화 + 1종 가정 검정
(평행추세 미성립)"**이 정확한 표현이다 — 발표·자소서에도 이 표현을 쓸 것.

### ★ V8 사전추세 검정 — 발표 전 반드시 이해하고 갈 것
V8은 DiD(V3)의 식별가정인 **평행추세**를 이 프로젝트의 자체 데이터로 직접 검정한다. 결과:

- 제도 시행 **이전**(2010~2015)에 이미 처치군-대조군 격차가 **연 -1.38%p**로 좁혀지고 있었다(t=-2.41).
- 이 추세를 통제하면 post 효과가 **+2.44%p (p=0.31)** 로 부호가 뒤집히고 유의성도 사라진다.
- 관측 셀도 처치군 연 20~163 사람-연도·사건 1~11건으로 매우 작다.

→ 즉 **"DiD로 -4.03%p 인과효과를 확인했다"고 말하면 안 된다.** 정확한 표현은
"제도 변화와 같은 방향의 움직임이 데이터에 있다는 정합성 확인"이며, 인과 주장은 하지 않는다.
`V8.passed=True`는 "평행추세가 성립한다"가 아니라 **"검정을 실제로 수행하고 결과를 공개했다"**는
뜻이다(그래서 method가 computed가 아니라 diagnostic이고, 통과 집계에서 빠져 있다).
가정 성립 여부는 `parallel_trends_ok` 필드(현재 `false`)로 판단한다.

면접·발표에서 이건 약점이 아니라 강점이다. 자기 대표 결과에 스스로 반증 검정을 걸고
결과를 그대로 공개하는 것이 "돌려봤더니 되더라"와 실제 분석을 가르는 지점이다.

## 4. 흔한 오류
- `ModuleNotFoundError` → 2번 pip install 다시
- `FileNotFoundError: params_v2.json` → 파일이 코드와 같은 폴더에 없음
- 웹앱 화면이 하얗게 멈춤 → 반복 횟수를 50으로 낮추고 재실행
- 한글 깨진 PDF → `pip install reportlab --upgrade`

## 5. 자사 데이터로 쓰는 법
사이드바 입력만으로 충분하지만, 인구 자체를 자사 명부로 바꾸려면
`big_firm_sample_2023.csv`와 같은 형식(age, tenure, wage, hours, edu 5개 열)의
CSV로 교체하면 엔진이 그대로 자사 인력 기반으로 부트스트랩한다.
