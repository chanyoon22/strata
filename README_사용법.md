# STRATA — 설치·실행·사용 안내 (v3, 2026-11)

정년연장·재고용 제도가 바뀌면 **우리 회사** 채용·인건비·승진·인력 구성이 어떻게 달라지는지
미리 계산해 비교하는 도구입니다. 회사 인사 명부(CSV·엑셀)를 올리면 그 인원 그대로 계산합니다.

---

## 1. 실행

```
pip install -r requirements.txt
streamlit run app.py
```

브라우저가 열리면 화면 위 여섯 단계를 왼쪽부터 따라가면 됩니다.

| 단계 | 하는 일 |
|---|---|
| ① 회사 데이터 | 명부 올리기 → 자동 점검 → 인력 구조 진단(부서별 정년 도달 달력) |
| ② 가정·시나리오 | 퇴사율·채용 방식·임금 가정, **직군별 충원·숙련 기간**, 비교할 안 고르기, 직접 만들기, **실행** |
| ③ 결과 | 요약, 비교표, 연도별 추이, 비용 분해, **숙련 손실까지 보면(손익분기)**, 인력 구조, 부서별 영향 |
| ④ 우리 회사에 맞는 선택 | 판정 기준·한도·중요도를 넣어 맞춤 순위, 두 시나리오 맞비교 |
| ⑤ 결론이 흔들리는가 | 재고용 조건 25가지, 큰 가정 27가지, 가정별 영향, 108가지 설계 탐색 |
| ⑥ 리포트 | 해석문, 엑셀·PDF 내려받기, 설정 저장·불러오기, 모형 점검, 한계 |

화면 없이 한 번에 돌리려면:

```
python run_pipeline.py                      # 표준 표본
python run_pipeline.py 우리회사_명부.csv 2026   # 회사 명부(기준 연도)
python validation_v2.py                     # 모형 점검 11종
python -m pytest tests -q                   # 자동 테스트 107개
```

## 2. 우리 회사 명부 준비하기

**꼭 필요한 것은 세 가지**입니다. 열 이름은 자동으로 알아보고, 틀리면 화면에서 고칠 수 있습니다.

| 필요한 정보 | 이런 열이면 됩니다 |
|---|---|
| 나이 | `나이` 또는 `생년`(1975, 1975-03-02, 19750302 모두 가능) |
| 근속 | `근속연수` 또는 `입사일` |
| 임금 | `월급` 또는 `연봉` (원·천원·만원 단위 자동 추정) |

있으면 더 정확해지는 것: `부서`(부서별 진단), `직급`(승진 분석), `고용형태`(정규·촉탁 구분),
`주당근로시간`.

- 이름·사번은 필요 없습니다. 들어 있어도 읽는 즉시 버립니다.
- 임원, 파견·인턴 등 정년 규정 대상이 아닌 사람은 자동으로 빼고, 무엇을 뺐는지 알려줍니다.
- 올린 파일은 분석하는 동안에만 메모리에 머물고 저장되지 않습니다.
  **민감한 자료라면 이 프로그램을 회사 PC에 내려받아 실행하세요**(위 1번 명령 그대로).
- 형식이 궁금하면 `sample_data/roster_template.csv`(빈 양식)와
  `sample_data/sample_roster.csv`(가상 회사 예시)를 열어보세요.

**개인별 명부를 올리기 어렵다면** ① 단계의 "연령대 집계표로 입력"에서 연령대별
인원·평균 임금·평균 근속만 넣어도 됩니다(부서·직급별 분석은 불가).

**선택 자료 두 가지** — 올리면 결과를 더 믿을 수 있게 됩니다.

| 자료 | 무엇을 해주나 |
|---|---|
| 퇴사자 명부(나이·근속·사유, 최근 1~3년, 부서 있으면 더 좋음) | 우리 회사 실제 퇴사율을 계산해 넣고, 근속 구간별·직군별로 모형 예측과 실제의 차이까지 반영 |
| 몇 년 전 명부(지금 명부와 같은 형식) | 과거에서 출발해 오늘을 맞혀보는 검증. 모형이 우리 회사에 맞는지 숫자로 확인 |

## 3. 결과를 읽을 때 기억할 것

- **후보 / 제외** — '후보'는 다른 어떤 안에도 모든 항목에서 밀리지 않는 안입니다.
  판정은 평균만 비교하지 않고, 같은 난수로 돌린 반복 계산의 차이가 우연이 아닌지(95% 신뢰구간)와
  차이가 의미 있는 크기인지(기본 0.5% 이상)를 함께 봅니다.
- **현행 유지(S1)** 에는 회사가 지금 하고 있는 재고용 관행이 그대로 이어집니다.
  법이 더 높은 수준을 요구하는 안에서는 둘 중 높은 쪽을 적용합니다.
- **인건비 차이가 작게 나오는 이유** — 고령자가 남는 만큼 신입을 덜 뽑아 서로 지워지기 때문입니다.
  ③ 단계 "왜 차이가 나는가"에서 두 방향을 따로 볼 수 있습니다.
- **임금피크·임금체계 개편·희망퇴직을 넣은 안이 유리하게 나오는 것은 당연합니다.**
  줄어드는 인건비만 계산하고 노사 협의·사기 저하·법적 분쟁 비용은 계산에 없기 때문입니다.
- **숙련 공백** — 사람이 나간 자리가 다시 제 몫을 할 때까지의 손실(충원 기간 + 후임 적응기의 부족분)입니다.
  산업마다 다른 값을 STRATA가 정하지 않습니다. ② 단계 직군 표에 현장이 아는 두 가지(충원까지 몇 달,
  혼자 맡기려면 몇 년)를 넣으세요. 넣지 않으면 모든 직군에 같은 자리표시 값이 들어가고 화면에 표시됩니다.
- **손익분기** — 숙련 공백 1인-년을 돈으로 얼마로 볼지 정하지 않고, "평균 인건비의 몇 % 이상으로 보면
  이 안이 낫다"로 보여줍니다. 회사는 그 기준보다 큰지 작은지만 판단하면 됩니다.
- 전체 한계 목록은 ⑥ 단계에 항상 표시됩니다.

## 4. 배포(Streamlit Cloud)

이 폴더 **전체**를 GitHub 저장소에 올립니다(하위 폴더 `.streamlit/`, `sample_data/`, `tests/` 포함).
`requirements.txt`가 바뀌었으므로 올린 뒤 Streamlit Cloud에서 **Reboot**해야 합니다.

AI가 쓰는 해석 리포트를 켜려면 Streamlit Cloud의 Secrets에 다음을 넣습니다(없어도 기본 요약으로 동작).

```
ANTHROPIC_API_KEY = "본인 키"
```

## 6. 흔한 문제

- `ModuleNotFoundError` → `pip install -r requirements.txt`
- 명부를 올렸는데 "임금 단위를 확인해 주세요" → 열 맞추기에서 '월급/연봉'과 단위를 고치고 다시 읽기
- 직급 순서가 틀림 → ① 단계 직급 표의 '서열' 숫자를 직접 고치기
- 계산이 오래 걸림 → ② 단계에서 계산 정밀도를 '빠름'으로
